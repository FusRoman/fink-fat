# fink-fat-sql

Postgres sink of Fink-FAT: the table schema, the row shapes and the `COPY`
loaders that write the tracking state (a `BranchCollection` and its
observations) into the database read by
[`fink-fat-explorer`](../fink-fat-explorer/README.md).

It is shared by the `fink-fat convert --format sql` CLI, which does a full
reload, and the streaming pipeline, which reuses the same building blocks. The
schema and the row encoding therefore exist only once.

## Tables

`convert` bulk-loads 8 tables, joined by `branch_id` / `hypothesis_id` / `id`:

| Table | Content |
| --- | --- |
| `observations` | One row per alert: position, errors, magnitude, filter, epoch, MPC code. |
| `branches` | One row per live branch, with precomputed arc / night statistics. |
| `kf_bank` | Per-branch Kalman bank metadata (steps, absolute magnitude). |
| `branch_observations` | Branch ↔ observation join, in track order. |
| `hypotheses` | Hypotheses of each branch's Gaussian mixture. |
| `kf_state` | Kalman state of each hypothesis, with its dynamical family. |
| `branch_best_state` | Denormalized best-hypothesis state per branch, for the explorer homepage. |
| `archived_trajectories` | Archived trajectories and their final state. |

The same scripts also create, but never truncate, the tables owned by the
explorer (`orbit_fits`, `orbit_fit_failures`, `cnd_queries`,
`skybot_bulk_jobs`, `skybot_obs_status`) and by `fink-fat submit`
(`mpc_submissions`).

## Crate layout

| Path | Role |
| --- | --- |
| `src/rows.rs` | Plain row structs, one per table. No logic. |
| `src/build.rs` | Pure functions turning a `BranchCollection` into rows (unit-tested). |
| `src/family.rs` | Dynamical-family classification stored in the `dynamic_family` columns. |
| `src/schema.rs` | DDL wrappers and the `*_SQL` constants embedding the scripts. |
| `src/copy.rs` | `COPY ... FROM STDIN BINARY` loaders, one per table. |
| `src/load.rs` | `write_bulk_tables`: the full reload in one transaction. |
| `src/error.rs` | `SqlError`. |
| `sql/*.sql` | The DDL itself, kept as plain SQL so it can be read, diffed, linted and run with `psql`. |

The input is rows, not a file path: the CLI reads its observation Parquet
itself, and the streaming pipeline will build rows from the alert stream.

## Full reload (`write_bulk_tables`)

A single transaction:

1. Create the tables if absent, then migrate older schemas.
2. Drop the secondary indexes and foreign keys.
3. `TRUNCATE` the 8 tables.
4. `COPY` every table, in binary format.
5. Rebuild the indexes and foreign keys.
6. `ANALYZE`, then commit.

A failure at any step leaves the previous contents untouched. The 8 tables are
`UNLOGGED`: they are fully regenerated by every run, so skipping the WAL loses
nothing.

The scripts set `lock_timeout = '1min'`, so `convert` fails instead of queueing
indefinitely behind a long explorer query. They set no statement timeout,
because the bulk `COPY`s and index rebuilds legitimately run for minutes.

## SQL lint

The scripts are linted with [SQLFluff](https://sqlfluff.com) (style, Postgres
dialect, config in `.sqlfluff`) and [Squawk](https://squawkhq.com) (Postgres
DDL safety, config in `.squawk.toml`). Squawk rules that do not apply to an
offline bulk load are ignored per file, with the reason written next to the
`squawk-ignore-file` line. Both run in the pre-commit hook and in CI; from the
repository root:

```bash
pip install -r crates/fink-fat-sql/sql-lint-requirements.txt
sqlfluff lint crates/fink-fat-sql/sql            # `sqlfluff fix` to reformat
squawk --config crates/fink-fat-sql/.squawk.toml crates/fink-fat-sql/sql/*.sql
```

## Tests

Unit tests cover the pure row building (`cargo test -p fink-fat-sql`). The full
reload is tested end to end against a real Postgres by the root crate's
`tests/sql_convert.rs`:

```bash
docker compose up -d db
cargo test -p fink-fat --test sql_convert
```
